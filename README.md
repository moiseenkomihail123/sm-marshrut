# СМ-маршрут

Прототип маршрутизации пациентов по текстам протоколов УЗИ. Решение кейса СМ-Клиники, разработанное на хакатоне.

## Задача проекта

Помочь сотрудникам клиники выявлять значимые находки в текстовых протоколах УЗИ и формировать маршрут пациента к профильному специалисту.

## Реализованные возможности

- Импорт протоколов УЗИ из файлов DOCX.
- Анализ описания и заключения по словарям и правилам.
- Учёт заданных отрицаний и контекстных условий.
- Выделение находок с цитатами из исходного протокола.
- Определение приоритета.
- Формирование основного маршрута к специалисту.
- Отметка отдельных несоответствий для проверки.
- Просмотр протоколов, очереди маршрутов и сводки.
- Редактирование правил через интерфейс.
- Демонстрация последующих этапов маршрута с использованием модельного времени.

## Логика работы

1. Программа извлекает текст из протокола DOCX.
2. Определяет направление исследования по папке файла.
3. Выделяет описание и заключение исследования.
4. Сопоставляет текст со словарями и правилами.
5. Проверяет заданные отрицания и контекст.
6. Сохраняет найденные признаки, цитаты и сведения о сработавших правилах.
7. Определяет приоритет и профиль специалиста.
8. Создаёт основной маршрут и отображает результат в интерфейсе.

Если система обнаруживает несколько находок, она выбирает один основной маршрут по правилам приоритета.

Отметка несоответствия между описанием и заключением предназначена для проверки сотрудником.

## Архитектура и технологии

СМ-маршрут — локальное веб-приложение с монолитной архитектурой.

Основные компоненты:

- Интерфейс пользователя: HTML, CSS и JavaScript.
- Сервер приложения: Python и Django.
- Механизм анализа: словари, правила и регулярные выражения.
- Хранение данных: SQLite.
- Импорт документов: извлечение текста из DOCX.

Пользователь открывает приложение в браузере. Локальный сервер обрабатывает запросы, выполняет анализ и сохраняет результаты в базе данных.

Внешняя языковая модель при обработке протоколов в текущем прототипе не используется.

## Входные данные

Протоколы УЗИ в формате DOCX.

Файлы размещаются в data/protocols в папках соответствующих направлений:

- Молочная железа.
- Щитовидная железа.
- Органы малого таза.
- Желчный пузырь и брюшная полость.
- Предстательная железа.
- Вены нижних конечностей.

Название папки используется для определения направления исследования. При добавлении документов сохраняйте структуру папок демонстрационного набора.

## Выходные данные

Для обработанного протокола программа показывает:

- Найденные признаки.
- Цитаты из исходного текста.
- Основания срабатывания правил.
- Приоритет.
- Признак необходимости проверки.
- Профиль специалиста и основной маршрут,
  если сработало соответствующее правило.

Результаты сохраняются в SQLite и доступны через интерфейс приложения.

## Структура проекта

- config/ — настройки Django и основные веб-адреса.
- routing/ — анализ текста, модели данных,
  обработка действий и правила маршрутизации.
- routing/migrations/ — описание структуры базы данных.
- templates/ — шаблоны страниц.
- static/ — стили и клиентские скрипты.
- assets/ — ресурсы приложения, включая значок.
- data/protocols/ — документы для импорта.
- manage.py — команды управления Django.
- requirements.txt — зависимости проекта.
- launch_app.vbs — запуск приложения двойным щелчком.
- launch_app.ps1 — проверка сервера и открытие браузера.
- start_server.ps1 — запуск сервера в фоновом режиме.
- install_app.ps1 — создание ярлыков в Windows.

Виртуальное окружение .venv и рабочая база db.sqlite3 создаются локально при настройке.

## Установка и запуск на Windows

Требуется Python 3.10 или новее, совместимый с Django 5.2.

Для установки зависимостей требуется интернет.

### 1. Подготовка проекта

Скачайте репозиторий и распакуйте его.

Откройте командную строку в папке, где находится manage.py.

### 2. Установка зависимостей

Последовательно выполните:

```bat
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 3. Создание базы данных

Выполните:

```bat
.venv\Scripts\python.exe manage.py migrate
```

### 4. Загрузка документов и правил

Разместите демонстрационные DOCX в data/protocols, сохранив папки направлений.

Выполните:

```bat
.venv\Scripts\python.exe manage.py load_protocols
```

Важно: команда load_protocols удаляет существующие протоколы, находки, маршруты и правила, затем загружает документы и исходные правила заново.

Используйте её для первоначальной подготовки демонстрационной базы. Не выполняйте при каждом запуске. Изменения правил, сохранённые только через интерфейс, 
эта команда не сохраняет.

### 5. Обычный запуск

Дважды нажмите launch_app.vbs в папке проекта.

Запускатель проверяет доступность сервера, при необходимости запускает его и открывает приложение в браузере:

http://127.0.0.1:8000/

Для работы запускателя оставьте в проекте launch_app.ps1 и start_server.ps1.

Закрытие вкладки браузера не останавливает сервер, запущенный в фоновом режиме.

### 6. Создание ярлыка — необязательно

Из папки проекта выполните:

```bat
powershell -NoProfile -ExecutionPolicy Bypass -File install_app.ps1
```

Скрипт создаст ярлык «СМ-маршрут» на рабочем столе и в меню «Пуск».

После перемещения папки проекта создайте ярлыки заново.

### 7. Ручной запуск

Если запуск через launch_app.vbs недоступен, откройте командную строку в папке проекта и выполните:

```bat
.venv\Scripts\python.exe manage.py runserver
```

Откройте в браузере:

http://127.0.0.1:8000/

При ручном запуске оставляйте окно командной строки открытым. Для остановки нажмите Ctrl+C.

Не запускайте одновременно второй сервер, если приложение уже работает на порту 8000.

## Демонстрационные данные

Приложение поддерживает импорт DOCX из папки data/protocols.

Для публичной демонстрации используйте синтетические документы либо материалы, публикация которых разрешена и которые не содержат персональных данных.

Если документы не включены в репозиторий, их необходимо подготовить и разместить в папках направлений перед загрузкой.

Набор документов для разработки сам по себе не является независимым эталоном для оценки клинической точности.

## Ограничения прототипа

- Анализ зависит от набора реализованных правил.
- Новые формулировки могут приводить к пропускам или ошибочным срабатываниям.
- Клиническая точность требует независимой  экспертной оценки.
- Подготовка к промышленной эксплуатации, включая безопасность и управление доступом, требует дополнительной проверки.

Прототип помогает организовать проверку и маршрутизацию. Медицинские решения принимает специалист.
